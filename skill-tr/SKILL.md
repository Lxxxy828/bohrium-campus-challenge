# 文献翻译 Skill（阅读03｜文献翻译）

本 Skill 是一个**纯指令型工作流**，指导 Agent 把真实科研文献翻译成可复核的双语对照结果。
它不依赖脚本，所有规则都要求 Agent 按步骤**实际执行**并留下证据，而不是把术语表、段号、
核验等要求"写进提示里了事"。

## 0. 运行时契约（先读，不可违反）

- 输入：`/input/case.json`（任务说明 + 材料路径 + 输入约束）与 `task.md`。
  **实际 PDF/材料是唯一事实依据**，不得依据文件名、标签或记忆中的同名论文补造内容。
- 工作目录：`/app/work`；中间产物（术语表草稿、切分清单、核验日志）可写在这里。
- 最终结果：写入 `/app/output/result.json`，必须包含 `case_id` 与下面"输出契约"的全部字段。
- 预算：64 次模型请求、900 秒、单次响应 ≤16384 tokens。要**先保存诚实的分阶段结果**，
  再逐步改进，不要一次性追求全篇而在中途丢失结果。
- 本 Skill 只提交文本资源（SKILL.md + README.md），不含脚本；运行时可用平台提供的
  PDF 文本/渲染/OCR 工具读取材料。

## 1. 目标与四个质量关口

目标：把一篇（或题面指定的段落区间）真实科研文献，产出**段落级双语对照**结果，使读者
能按段号回看原文、核对译法，并得到术语表、核验证据与未译/不确定清单。

四个质量关口是本 Skill 的验收线，缺一不可，逐条对应 `result.json` 中的字段：

| 关口 | 验收标准（不满足即记入 uncertainties 并影响 status） |
|-|-|
| **术语稳** | 同一术语在标题、摘要、正文、图注、表头、结论中使用**同一译名**；术语表是硬约束，全篇回填后给出术语一致率。 |
| **段落全** | 跨页、跨栏、跨章节不漏段、不重复、不错位；段号（`para_id`）与原文一一对应，覆盖任务要求的全部要素（全文段落、图题/表头、公式与编号、引用标记、术语表条目）。 |
| **关系准** | 指代对象、否定与限定、因果与让步、数字与单位、公式、文献编号均与原文一致，不凭"读起来通顺"改写关系。 |
| **可核验** | 每段译文给出原文定位（页码/段号/栏位/章节）与译法依据；译不准、读不出、拿不准处显式标注，不含混。 |

## 2. 分步工作流（按顺序执行，每步产出可检查的中间物）

### Step 0 — 读取任务与识别边界
1. 读 `/input/case.json` 与 `task.md`，记录：`case_id`、材料文件路径、要求的翻译范围
   （全篇/某页/某节/某要素）、语言方向（默认 源语言→简体中文）、必须覆盖的要素清单。
2. 明确"事实依据 = 材料文件本身"。若题面与材料冲突，以材料为准并记入 `notes`。

### Step 1 — 读取材料并检查文本层
1. 优先用 PDF 文本工具抽取文字层；确认是否有文字层、是否多栏、是否含扫描页。
2. 检查抽取结果的完整度（页数、段落是否连续、公式/表格/引用是否可读）。
3. 若某页无文字层或为扫描件：用 OCR 工具识别，并给该页内容加 `[OCR]` 标记与置信度，
   这类内容一律视为"需人工确认"，不视为可靠原文。
4. 把抽取的原文按页保存为 `source_text.md`（`/app/work` 下），供全篇回查与 grep 使用。

### Step 2 — 段落切分与编号（对应"段落全"）
1. 以**语义段**为最小翻译单元，切分边界为：标题、作者/单位、摘要、章节标题、正文段、
   图题（Figure 1 ...）、表头（Table 1 ...）、公式（含编号）、脚注、参考文献条目。
2. 每段分配 `para_id`：
   - 原文自带编号（如正文 "1.", "2.", 公式 "(1)"，引用 "[12]"）→ 沿用原文编号；
   - 原文无编号（摘要、图题等）→ 按出现顺序 `P1, P2, …` 连续编号；
   - **禁止重排、跳号、合并或拆分导致原文段落与译文段落无法一一对应**。
3. 记录每段的定位 `src_loc`：页码、栏位（单栏留空/左/右）、章节、原文起止（前 20 字 + 末 20 字）。
4. 建立 `切分清单`（segment index）：`para_id → src_loc → 原文首尾指纹`。这是"不漏不重不错位"
   的对照基准，翻译完成后逐项勾销。

### Step 3 — 术语表抽取与锁定（对应"术语稳"）
术语表是**硬约束**，不是附录。执行方法：
1. 建立 `术语表`（格式见 §4），初始为空。
2. **抽取**：逐段翻译前，先扫出该段的领域术语/缩写/专名；与表内比对：
   - 新术语 → 先查其常见中文译名，确定唯一译名后**写入术语表**并分配 `term_id`；
   - 已有术语 → **只允许使用表内译名**，不得即兴换词。
3. **锁定**：`translation` 字段一旦写入即锁定。后续若发现译名确有错误需要改，必须：
   在 `notes.change_log` 记录 `term_id + 旧译名 + 新译名 + 理由`，并回改全篇该术语的旧译名。
4. **全篇回填**（Step 6 再做一次强制核对）：把术语表每个源术语在标题/摘要/正文/图注/表头/
   结论中出现的每一处，grep 对应译文是否用同一译名；统计
   `术语一致率 = 1 − 不一致次数 / 术语总出现次数`，写入 `notes`，不一致处列入 `uncertainties`。

### Step 4 — 逐段翻译（带上下文，对应"段落全"+"关系准"）
对每个 `para_id` 按序翻译，每次只译一段，但**必须携带上下文**：
1. 携带前一段的**末句**（前文）与当前段的**下一段首句**（后文线索），用于判定指代。
2. 携带当前章节标题与已锁定的术语表。
3. 翻译规则：
   - 指代（it/this/前者/后者）：先明确指代对象再译，必要时在译文中补出对象并写进"译法依据"。
   - 否定/限定/因果/让步：逐句保留逻辑词（不、并非、仅、除非、因为、尽管、然而、因此等），
     不得因顺口而删除或反转。
   - 数字与单位：数值照抄，单位用规范译名（如 mg/mL、°C、mmol/L），保留原文单位符号不变；
     若做任何换算/归一，必须显式写出换算关系。
   - 公式：**不译**，保留 LaTeX/原文形式与公式编号（如 (3)）；变量符号不翻译。
   - 引用标记：保留原形式 `[12]`、`(Smith et al., 2020)`，不译作者名与编号；可附中文"等人"。
   - 图题/表头：作为独立段翻译并保留图/表编号。
4. 每段产出一个双语对照对象（结构见 §5 `paragraphs[]`）。
5. **跨页/跨栏接续检测**：若一段在页底或栏底被截断（句号未闭合、编号跳跃、下一段首行是
   残句），不要单独硬译；先标记 `[跨页接续]`，拉取下一页/下一栏首部拼接完整后再译，保证
   不漏不重。原文存在且未截断的段落才允许作为完整段输出。

### Step 5 — 关系核验（对应"关系准"）
每译完一段，立即做一次**关系 diff**（原文 vs 译文），逐项勾对：
- 数字与单位：数量、量纲、数量级是否一致；
- 公式：符号、上下标、编号是否保留；
- 引用编号：[n]、(Author, year)、图/表编号是否保留；
- 否定/限定/因果/让步：逻辑词是否保留且方向正确；
- 指代：译文中的"其/它/该"能否唯一回溯到原文对象。
任何不一致 → 回改译文；改不动 → 记入该段的 `不确定项` 与全局 `uncertainties`。

### Step 6 — 全篇回填与一致率（对应"术语稳"+"段落全"）
1. 按 `切分清单` 勾销：原文段数 == 译文段数，`para_id` 一一对应，无漏/重/错位。
2. 术语全篇回查（见 Step 3.4），输出术语一致率与不一致清单。
3. 统计覆盖要素：全文段落、图题/表头、公式与编号、引用标记、术语表条目是否全部包含。
4. 把数字/单位/公式/引用的差异清单汇总为 `核验日志`，作为 `evidence` 的来源。

### Step 7 — 自检清单与输出（对应"可核验"）
输出前逐项自检（全部通过才写 status=success）：
- [ ] 每段译文都有 `原文定位` 与 `译法依据`，且原文定位能实际回到材料；
- [ ] `para_id` 与原文一一对应，无漏段/重段/错位；
- [ ] 术语一致率已计算，不一致项已列入 `uncertainties`；
- [ ] 数字/单位/公式/引用编号逐项 diff 通过，异常已列入 `uncertainties`；
- [ ] 所有读不出、拿不准、需人工确认处已显式标注，未冒充确定结果；
- [ ] `status` 与 `uncertainties` 反映真实完成度（有未决项则 partial，未开始则 failed，拒答则 refused）。

## 3. 输出契约（写入 /app/output/result.json）

字段名与题意一致：`case_id` / `status` / `译文结果` / `术语表` / `evidence` / `uncertainties` / `notes`。
`status` 取值：`success`（全部关口通过、无未决项）/ `partial`（有未决或未完成部分）/
`failed`（无法完成主要翻译）/ `refused`（拒答并说明原因）。

```json
{
  "case_id": "string，与输入一致",
  "status": "success | partial | failed | refused",
  "status_reason": "string，一句话说明为何取此状态",
  "译文结果": {
    "language_pair": "en→zh_CN 等",
    "source": "材料文件名与页码范围",
    "covered_elements": ["正文段落", "图题/表头", "公式与编号", "引用标记", "术语表条目"],
    "paragraphs": [
      {
        "para_id": "P1 或原文编号",
        "src_loc": {"page": 2, "column": "left|right|null", "chapter": "引言", "span": "原文前20字…原文末20字…"},
        "原文": "该段原文（含公式/引用标记原样保留）",
        "译文": "该段译文",
        "译法依据": ["term_id T01: X→Y（术语表）", "指代 it→主语X（见前段）", "公式(3)保留", "否定 not 译作'并非'"],
        "不确定项": ["如：OCR 置信度低的词；指代候选两个"]
      }
    ],
    "tables_figures": [{"ref_id": "Figure 1", "原文": "...", "译文": "...", "src_loc": {"page": 4}}],
    "formulas": [{"eq_id": "(3)", "原文": "…", "译文": "保留原文", "src_loc": {"page": 5}}],
    "references": [{"ref_id": "[12]", "原文": "...", "译文": "保留原文", "src_loc": {"page": 11}}]
  },
  "术语表": {
    "format": "table",
    "entries": [
      {"term_id": "T01", "source_term": "原文术语", "translation": "锁定译名",
       "domain": "学科领域", "first_occurrence": "P3/第2页",
       "note": "缩写/异名/备注（可选）"}
    ]
  },
  "evidence": [
    {"claim": "关键结论或翻译要点", "location": "第2页第3段(P3)"},
    {"claim": "术语一致率 100%", "location": "全篇回查结果，见 notes.term_consistency"}
  ],
  "uncertainties": [
    "未报告/无法判断/材料冲突项，逐条列出并给位置"
  ],
  "notes": {
    "change_log": [{"term_id": "T01", "old": "…", "new": "…", "reason": "…"}],
    "term_consistency": {"checked": 42, "inconsistent": 0, "rate": "100%"},
    "segment_coverage": {"source_paras": 31, "translated_paras": 31, "rate": "100%"},
    "selfcheck_passed": true,
    "extra": "其他说明"
  }
}
```

约束：
- `evidence` 必须给出**可回到原文的定位**（页码/段号/栏位/字段），不能只写"见原文"。
- `uncertainties` 是必填字段；没有不确定项时写 `[]`，但若 status=partial 则必须非空并解释。
- `译文结果.paragraphs[]` 是**段落级双语对照**：每个对象同时含原文与译文，禁止只给译文。

## 4. 术语表格式与强制执行的细节

术语表条目最小字段：`term_id / source_term / translation / first_occurrence`；
`domain / note` 可选。术语表在 `/app/work/glossary.json` 维护，最终随 `术语表` 字段写入结果。

"强制"体现在三个动作，缺一不可：
1. **抽取即登记**：新术语必须先入表、再用于翻译（先定名，后动笔）。
2. **全篇只认表**：翻译时命中表内术语，译文必须等于 `translation`；否则视为一次"不一致"。
3. **回填即校验**：翻译完成后对每个源术语的每次出现，回查译文是否用同一译名，输出一致率；
   任何不一致要么回改，要么写入 `uncertainties` 并说明无法回改的原因。

缩写与异名处理：源术语出现缩写（如 BMI）或异名（如 "type 2 diabetes" vs "T2D"）时，
在 `note` 记录其别名并统一指向同一 `translation`，全篇按别名回查。

## 5. 段号对齐约定

- 语义段是唯一对齐单位；`para_id` 在整份结果内唯一且稳定（重复运行应得同一编号）。
- 原文自带编号优先沿用；无编号按出现顺序 `P1..Pn`。跨页被截断的段**合并后仍只占一个 para_id**，
  不得拆成两个导致错位。
- 图题/表头/公式/参考文献条目是**独立段**，纳入同一 `para_id` 序列（或按其自带编号），
  保证"要素全覆盖"可被统计。

## 6. 未译标注规则

以下情况一律保留原文并显式标注，禁止硬译或含混带过：
- 公式、变量符号、上下标 → 保留原文形式；
- 引用标记 `[n]` / `(Author, year)` → 保留，作者名可加"等人"；
- 专有名词/软件名/数据库名/基因名/物种学名 → 保留或采用学界通用名，无把握则保留原文；
- OCR 不确定、文字层缺失、扫描模糊 → 标 `[OCR不确定: …]` 并列入 `uncertainties`；
- 指代无法唯一确定 → 译文中保留代词并附候选对象，标注"所指未明"；
- 材料中两处矛盾 → 两处都如实给出，标 `[材料冲突]`。

标注语法统一为 `【待核：…】` 或 `[OCR不确定: …]`，保证可被复核者直接检索。

## 7. 异常与边界处置

| 异常 | 处置 |
|-|-|
| 无文字层/扫描件 | 用 OCR 读取，全部标 `[OCR]` 与置信度，视为需人工确认；status 至少 partial。 |
| 公式/表格是图片 | 保留图片位置说明 + OCR 内容，标注"待人工确认"；不伪造可编辑公式。 |
| 参考文献无法解析 | 逐条保留原文，标注"未译（引用标记保留）"。 |
| 原文残缺/页码缺失 | 只译能读到的部分，缺失处记入 `uncertainties` 并给缺失位置。 |
| 语言混杂（中英混合） | 只译需翻译的部分，已有中文/公式/引用保持原样。 |
| 超长文/预算不足 | 按段落区间分批，先写 partial 结果到 result.json 保底，再逐段改进；未译区间写清起止。 |
| 材料与题面冲突 | 以材料为事实依据，冲突记入 `notes`。 |
| 工具读取失败 | 重试一次；仍失败则 status=partial/failed，写清失败点，不编造内容。 |

预算铁律：**先落盘再润色**。第 1 版至少包含切分清单 + 术语表草稿 + 前几段双语对照并写入
result.json（status=partial）；之后每完成一批就覆盖保存，绝不空手等全篇。

## 8. 诚实性铁律

1. 读不出就是读不出：文字层缺失、扫描模糊、OCR 不确定处**不猜**，标注并列入 `uncertainties`。
2. 无法判断就是无法判断：指代、关系、译名无把握时保留原文并标注，不擅自补成"确定"。
3. 材料冲突要显式呈现：两处都列出并标 `[材料冲突]`，不替原文选边。
4. **禁止猜测、补造、伪造**：不补造原文段落、不补造引用、不伪造 DOI/页码/页数/数据。
5. 术语译名以可核查来源为准；无把握时保留原文 + 临时译名并标注，不臆造"权威译名"。
6. `status` 如实反映完成度：有未决项就是 partial，不要为了好看写 success。
7. 结果里的每个 `evidence` 都必须是真实可回查的定位，不做"看起来有依据"的泛化引用。
